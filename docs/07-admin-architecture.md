# MOA Admin — 1차 구조

현재 사용자 앱은 Expo/React Native, API는 NestJS, 공통 모델은 `@moa/domain`이다. API의 일반 `/api/snapshot`은 거래 당사자별 데이터만 제공하며 관리자 재사용 대상이 아니다. 거래 이벤트(`events`)가 상태 변경 시각·주체·사유의 원본이다. 배송사 실조회, PG, 실제 출금, 관리자 메모/조치 저장소는 아직 없다.

이번 범위는 `apps/admin`의 대시보드·거래 목록·거래 상세와 분리된 `/api/admin` 읽기 API다. React + TypeScript + Vite로 기존 React 자산을 활용하고, UI 데이터는 API 어댑터에서만 받는다. 컴포넌트에 예시 거래를 넣지 않는다. 데스크톱은 좌측 접이식 메뉴, 상단 검색, 표, 상태, 상세 타임라인을 우선한다.

보안 경계: 일반 사용자 세션은 Admin API에 사용되지 않는다. 운영자 이메일·scrypt 비밀번호 해시·TOTP는 서버 환경변수로 공급한다. 로그인 성공 시 서버 세션을 `HttpOnly`/`SameSite=Strict` 쿠키로 전달하고 모든 데이터 응답에 `no-store`를 적용한다. 현재는 읽기 전용이며 개인정보는 API 응답 전에 제거/마스킹한다. 채팅과 구매 증빙은 `OPERATIONS`/`CUSTOMER_SUPPORT`만, 금액은 `OPERATIONS`/`FINANCE`/`SUPER_ADMIN`만 볼 수 있다. 정산/환불/상태 변경 버튼은 실제 공급자와 감사 로그·승인 흐름이 준비되기 전까지 없다.

거래 상세 정보의 출처: 요청(상품·수령 방식), 제안(연결 여행), 여행·방문 일정, 거래 금액, 모의 결제와 보관금, 구매 증빙, 배송 등록, 구매자 수령, 모의 정산·보관함 기록, 채팅, 분쟁, 이벤트 타임라인. 운송장 등록은 실제 배송사 추적 조회가 아니며, `TRAVELING`은 여행자가 귀국 준비를 선언한 상태이지 항공편 검증이 아니다. 시각/주체/사유가 없는 상태는 추정하지 않고 `기록 없음`으로 표시한다.

다음 단계: 전용 관리자 DB·역할 관리, 영속 세션/감사 로그, CS 메모와 승인형 조치, 배송사/PG 연동, 인덱스 기반 조회. 현 Nest 저장소는 작은 프로토타입용 전체 컬렉션 읽기이므로 10,000건/일 규모의 SLA를 주장하지 않는다. `NODE_ENV=production` 기동 차단도 유지한다.

운영자 계정은 현재 환경변수로 설정하는 단일 부트스트랩 계정이다. 여러 운영자의 개별 신원과 영속 로그인 이력, 개인정보 열람 감사 로그가 필요하므로 이 상태를 운영 배포 가능한 인증 시스템으로 간주하지 않는다.
