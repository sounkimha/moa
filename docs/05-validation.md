# UI/UX 통합 검증 · 2026-09-15

## 실행 환경

macOS. 최종 API 테스트·웹 빌드·DOM 흐름은 Node.js 24.19.0으로 실행했다. 시스템 기본 Node 22.12.0은 프로젝트 최소 요구 22.13.0보다 낮으므로 지원되는 Node를 사용하는 것이 좋다. 의존성 버전은 package-lock.json을 기준으로 한다.

## 이번 변경 검증

| 검증 | 결과 | 범위 |
|---|---|---|
| `npm run typecheck` | 통과 | 모바일·API·공유 도메인 |
| `npm run lint` | 통과 | ESLint 제어 흐름·디버깅 오류 규칙; 스타일/전체 접근성 검사를 대신하지 않음 |
| `npm test` | 101개 통과 | 실제 임시 HTTP API, 도메인, 원장, 인증·세션 경쟁, 폼 편집·취소, 초안, 지도 오류, PGlite |
| `npm run build` | 통과 | 공유 도메인·API 컴파일·Expo 웹 export |
| `scripts/ui-smoke.mjs` | 통과 | 실제 웹 bundle + 임시 Nest API + jsdom |
| `git diff --check` | 통과 | 공백 및 패치 오류 |
| `scripts/browser-audit.py` | 통과 | 별도 headless Chrome, 360×800 / 390×844 / 548×734, 임시 API와 새 브라우저 세션 |
| 네이티브 실기기 QA | 미완료 | iOS/Android 실제 기기·키보드·접근성 검증은 별도 |

이전 버전의 브라우저/iOS/Android export 기록을 이번 변경의 통과 결과로 사용하지 않았다. 앱 내 브라우저 제어는 도구 실행 오류로 사용할 수 없어, 현재 export를 별도의 headless Chrome에서 검사했다. 브라우저 검사는 장소 검색을 명시적 테스트 응답으로 대체하며 외부 지도 스크립트 실패·외부 폰트 미연결 상태를 사용한다. 실제 지도 타일·카카오 검색·외부 폰트의 품질, 실제 기기의 키보드 동작을 통과했다고 판단하지 않는다. jsdom 통과와 Chrome 레이아웃 통과도 구분한다.

## 직거래 희망 장소 집중 재점검

- 최초 직거래 선택 후 취소하면 원래 국내 택배 선택으로 복원한다.
- 검색 결과 선택 → 상세 위치 저장 → 다시 편집 → 취소 시 이전 확정 좌표·설명을 유지한다. 편집 중인 값은 저장 전 요청 초안에 반영하지 않는다.
- 새로고침·이전 단계 이동 후 확정 위치·전달 방식·보상금을 유지한다. 수령 지역 변경 시 이전 지역의 좌표를 그대로 사용하지 않는다.
- 장소명 검색 설정 여부를 먼저 확인한다. 키가 없으면 미연결 안내를 보이며 가짜 검색 결과로 대체하지 않는다.
- 지도 라이브러리·타일 실패 또는 시간 초과에 오류·재시도를 제공한다. 타일이 보이기 전에 빈 지도 중심을 확정 좌표로 전달하지 않는다. 스크립트/타일 실패와 좌표 검증은 별도 테스트로 확인했다.
- 현 작업 환경에서는 카카오 실검색 키 연결을 확인하지 못했다. `apps/api/.env`의 `KAKAO_REST_API_KEY` 설정·서버 재시작과 실제 검색 검증이 필요하다.

## 검증한 핵심 흐름

- 장소/도시가 상품 입력보다 먼저 나오는 홈, + 등록 선택 시트, 집중형 등록 화면의 하단 탭 숨김.
- 국가 전체 → 도시·섬 검색과 복수 선택 → 실제 방문지 선택.
- 도시를 추가해도 기존 매장 2곳과 섬의 방문지 유지; 자동 방문지 추가 없음.
- 날짜 범위 선택 취소 시 기존 귀국일 유지; 화면 재진입 및 계정별 초안 복원.
- 웹 체크박스의 aria-checked, 탭의 aria-selected, 버튼의 비활성·진행 상태 전달.
- 도시별 사진·사진 출처 → 장소 상세 → 이전 화면/주소 동기화.
- 예시 링크/사진 상품 채우기 → 배송/직거래 지도 선택 → 구매자 보상 입력 → 뒤로가기 후 유지 → 등록.
- 여행자 홈 → 장소별 묶음 → 구매자가 지정한 보상 확인 → 수락.
- 모의 카드 선택 → 결제수단 확인 → 금액 동의 → 결제 → 구매 인증 → 국내 운송장 입력 → 수령 → 구매 확정 → 정산.
- 구매 실패 전환, 환불/재부탁, 권한·중복 명령·동시 수락·정산 반올림.
- 인식 미연결·지도 실패·잘못된 저장 데이터와 영어 내부 오류의 한국어 복구 안내.
- 테스트한 DOM 흐름에서 React runtime 오류 없음. 실제 스크린리더 검증은 별도다.
- 취소된 링크 재인식, 늦게 도착한 인식 응답과 직접 입력의 경쟁, 잘못된 날짜·가격·주소 검증.
- 저장소 제한 중 로그인, 로그아웃 후 늦은 인증 응답, 계정 변경 뒤 이전 요청 응답, 새로고침 401 처리와 기본 배송지 유지.
- 오래된 제안 수락 시 현재 일정·인증·귀국 국가·직거래 도시·보상 재검증; 없는 거래와 잘못된 권한·단계의 직접 URL 진입 방어.
- 하단 알림이 버튼 터치를 가로채지 않도록 처리했다.

API 테스트는 합성 항공권/모의 공급자 응답/임시 저장소를 사용한다. 실제 티켓, 카드번호나 계좌번호를 수집하지 않는다.

## 남은 검증과 연동

- Chrome 360/390/548px의 주요 흐름·가로 넘침·날짜 확인 버튼의 화면 내 배치를 검사했다. iPhone 12 Pro·Android 실기기의 키보드·큰 글자·포커스·스크린리더 QA는 아직 필요하다. 브라우저 viewport 검사는 실기기 검증을 대신하지 않는다.
- 앱 첫 이해 5초, 부탁 등록 30초는 목표이며 사용자 테스트로 측정하지 않았다.
- 소셜 로그인 운영 키, 본인인증, 발권 확인, 실제 PG/webhook/정산, 외부 재고·지도 품질·AI 인식/번역 품질 검증이 남았다. 체험 성공은 실제 인증·결제 성공이 아니다.
- 웹 출발 도시 GPS 역지오코딩은 현재 라이브러리에서 지원하지 않아 직접 선택하도록 안내한다. 홈의 위치 좌표 확인과는 다르다.
- 국가·섬·방문지는 등록된 카탈로그 범위다. 실시간 전 세계 장소 검색·실재고 확인·검증된 최적 동선이 아니다.
- 여행 초안은 웹 탭 새로고침 시 복원한다. 네이티브 앱 프로세스 재시작 이후의 초안 저장은 미연결이다.
- 부분 재고·현장 가격 차액의 재승인, 운영 분쟁/환불·개인정보 보관 정책은 별도 구현이 필요하다.

## 의존성 점검

개발용 ESLint와 TypeScript parser를 추가했다. 설치 로그에는 기존 Expo/Nest 의존성 경로 관련 취약점 19건(보통 7, 높음 12)이 보고됐다. 로컬 lock 비교에서 기존 패키지 버전 변경은 없으며 새 항목 79개는 모두 개발 의존성이다. 캐시된 감사 항목은 image-size, multer, postcss, uuid였다. 별도 최신 외부 감사는 의존성 메타데이터 전송 승인 제한으로 실행하지 않았다. 운영 배포 전 별도 보안 점검과 호환성 검증이 필요하며 자동 강제 업그레이드는 하지 않았다.

## 직접 확인

`npm run dev` 후 [로컬 앱](http://localhost:8081/#home)을 연다. 390px와 360px에서 홈 → 등록 → 여행지/방문지/달력 → MY/모드 → 거래 순으로 확인한다. Python 3의 Playwright·requests와 Google Chrome이 설치된 환경에서는 `npm run test:browser`로 현재 UI의 별도 Chrome 회귀 검사를 실행할 수 있다. 임시 서버를 직접 시작하므로 `npm run dev`가 필요하지 않으며 실행 중 사용자 데이터는 변경하지 않는다. 캡처는 임시 `moa-layout-results-*` 폴더에 남고 정확한 경로를 출력한다.
