## 서버 테스트 상세

1. 비로그인 snapshot 차단과 Codespaces demo login preflight 허용.
2. 상품 메타데이터·사진 인식의 성공, 불확실, 차단, 수동 fallback 처리.
3. 아시아 국가·도시·현지 통화·소수 가격과 여러 도시 일정 검증.
4. 음수 금액·제외 카테고리·잘못된 날짜·배송 누락·자기 제안·기간 불일치 차단.
5. 귀국 후 국내 택배/직접 전달 정책과 기존 국제 배송 데이터 마이그레이션.
6. 장소별 묶음의 원자적 저장, 개별 제안 보상금, 중복 ID와 불완전 보상표 차단.
7. 동시에 제안 두 개를 선택해도 거래 하나만 생성하고 채팅을 함께 개설.
8. 상품 사진 또는 영수증 한 장만으로 구매 인증 가능, 둘 다 없으면 차단.
9. 품절·구매 불가 증빙 시 거래 종료, 결제·에스크로 전액 환불, 재요청 가능.
10. Mock 결제 실패·성공 재시도·채팅 재시도의 중복 기록 방지.
11. 구매 → 전달 준비 → 배송 → 수령 → 구매 확정 → 정산 전체 흐름과 정산 분리.
12. 타인 증빙·보관금·대화 접근 차단, 분쟁 시 보관금 동결과 정산 차단.
13. 파일 저장소 재시작·실패 rollback·기존 영수증 결과값 보정.
14. PostgreSQL DDL·seed·FK·금액 CHECK를 실제 PostgreSQL 호환 엔진에서 검증.
15. 보관함 결제의 단일 차감·정확한 환불, 정산금 적립, 잔액 초과/중복 출금 차단.
16. Mock PASS/SMS 확인 전 정산계좌 등록 차단, 충전·출금 멱등성, 민감 계좌정보 미저장.

## DOM 통합 시나리오

자동화는 소스를 모사한 별도 화면이 아니라 **실제로 export된 React Native Web JavaScript**를 실행한다.

- 온보딩 → 가상 세션 발급 → 예시 상품 링크 입력 → 새 요청 저장.
- 여행자 홈 → 시부야 묶음 선택 → 부탁별 보상금 입력 후 수락.
- 구매자 제안 → 여행 경로와 시간 확인 → 결제수단 선택 → 모의 결제 → 상대 계정 전환 → 구매 증빙 → 배송 → 수령·구매 확정 → 여행자 보관함 정산 → Mock 본인확인·출금.
- 구매 결과에서 구매 성공/구매 불가 전환, 증빙 전 환불 버튼 비활성화, 품절 안내 확인.
- 해당 흐름의 React runtime error 없음.

## 실제 브라우저 화면 검증

- 320px, 390px, 1440px에서 온보딩·로그인·도시 사진·장소 상세·보상 입력을 확인했다.
- 같은 세 해상도에서 상품/영수증 업로드 선택지와 품절 사유·방문 증빙·환불 CTA를 확인했다.
- 모든 로컬 관광지 이미지 로딩, 가로 스크롤 없음, React/browser runtime error 없음을 자동 단언했다.

## 확인하지 못한 범위

- Xcode/Gradle 네이티브 바이너리 빌드, 앱 설치·실기기 입력/권한/키보드/스크린리더 테스트는 미실행이다. iOS·Android Hermes export 성공까지 확인했다.
- Docker PostgreSQL 서버와 Redis의 실제 컨테이너 통합은 미실행이다. PostgreSQL SQL 구문·제약은 embedded PostgreSQL 엔진에서 검증했다.
- 실 OAuth·휴대폰/계좌 인증·PG·외부 지도·S3·사진 진위 판독·외부 상품 크롤링은 미연결·미검증이다.
- 요청 수량 일부만 재고가 있거나 현장 가격이 달라진 경우의 부분 구매·차액 재승인 흐름은 아직 없다.
- 30초 등록·1분 일정 등록은 UX 목표이며 사용자 실험으로 측정한 결과가 아니다.
