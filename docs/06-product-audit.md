사용성 목표인 “서비스 이해 5초”와 “부탁 등록 30초”는 아직 사용자 테스트로 측정하지 않았다. 화면 동작·모바일 레이아웃 검사만으로 해당 목표 달성을 주장하지 않는다.

## 오류 재점검 · 직거래 희망 장소

- 직거래 위치·수령 지역·배송지·출발지 시트의 편집값과 확정값을 분리했다. 취소하면 이전 선택을 복원하고, 미확정 위치는 초안에 저장하지 않는다. 처음 직거래를 열었다 취소한 경우 국내 택배로 돌아간다.
- 장소명 검색 설정을 먼저 확인하고 미연결 상태를 안내한다. 지도 스크립트·타일 실패/시간 초과에는 재시도를 제공하며, 빈 지도에서 좌표가 확정된 것처럼 처리하지 않는다. 실제 카카오 검색에는 서버 키 설정이 필요하다.
- 중단한 링크를 다시 인식할 수 있게 했고, 늦은 인식 응답이 새 입력을 덮어쓰지 않도록 했다. 알 수 없는 구매 장소를 임의의 매장으로 자동 지정하지 않는다.
- 잘못된 날짜·가격·주소 검증, 기본 배송지 유지, 저장소 제한 중 로그인, 로그아웃·계정 전환 이후 늦은 응답과 401 처리를 보강했다.
- 오래된 제안 수락 시 일정·인증·수령 국가/도시·보상을 서버에서 재검증한다. 사라진 데이터나 잘못된 권한·단계로 거래 화면을 직접 열어도 중단되지 않도록 했다.
- 하단 알림이 화면 버튼의 터치를 가로채지 않도록 했다.

## 이전 점검의 범위와 소스 동기화 기록

GitHub `origin/main`의 웹 편집 커밋 `ee94fea`를 fetch한 뒤 로컬 `main`에 fast-forward로 반영했다. 웹 편집본의 아시아 도시 사진, 거래 체험 흐름, 품절·구매 불가 처리, 개발 프록시 개선을 기존 로컬 항공권 확인·초안 보존·가격 및 매칭 수정과 함께 합쳤다. 충돌 파일은 제품 정책에 맞춰 수동 통합했으며 강제 덮어쓰기·push는 하지 않았다. 통합 전 로컬 상태는 `stash@{0}`에 안전 사본으로 남겼다.

기존 Expo/React Native/TypeScript, NestJS, 공통 도메인 구조를 유지했다. 구매자/여행자 화면, 요청·묶음·거래·계정, 상태/경로, 가격 및 수락 검증, 인증·저장소·API 오류 처리를 점검했다. 전체 서비스 출시 검증이나 모든 화면의 전수 검증을 완료했다는 의미는 아니다.

## 항공권 확인의 구현 경계

`POST /api/trips/:id/flight-proof`는 소유자 인증, 필수 개인정보 처리 동의, 이미지 제한, QR/바코드 인식, 선택 OCR, 왕복 일정 대조를 수행한다. 원본/이름/예약번호/QR 원문을 저장하지 않으며 타인의 snapshot에 대조 결과를 포함하지 않는다. 예약 링크 QR은 따라가지 않는다.

연도 없는 탑승권 코드는 연도 확인 필요로 표시한다. 일정 일치는 `PENDING_REVIEW`, 불일치는 `NEEDS_REVIEW`이며 최종 인증으로 승격하지 않는다. 새 일정은 단건·묶음 수락과 예전 제안 매칭 모두 차단한다. 실제 발권/본인확인 연동 없이는 진짜 여행 인증이나 노쇼 방지를 보장할 수 없다.

## 코드 구성과 검증 범위

- 경로 파서/직렬화는 `state/navigation.ts`, 웹 탭 초안 검증/저장은 `state/draft-session.ts`로 분리했다. 민감한 주소·사진·토큰을 경로 URL에 넣지 않는다.
- 기존 거래 원장·멱등성·리비전·권한·파일 저장 및 PostgreSQL 테스트를 유지했다. `mobile-state.test.cjs`, `matching-logic.test.cjs`, `flight-proof.test.cjs`에 회귀 테스트를 추가했다.
- 이번 변경의 TypeScript·lint·자동 테스트 101개·웹 빌드·DOM 흐름, 별도 Chrome 360/390/548px 회귀 검사를 통과했다. 실기기 검증과 실제 외부 검색·지도 공급자 검증은 남아 있다. 최종 실행 결과와 범위는 [05-validation.md](05-validation.md)를 기준으로 한다.
- `test:ui`에는 웹 export 빌드와 실제 API에 연결한 DOM 거래 흐름이 포함된다. OAuth 테스트는 허용 복귀 주소, 일회성 state/code, 서버 토큰 교환, 개인정보 비저장을 모의 공급자 응답으로 검사한다. jsdom 통과는 실제 브라우저 레이아웃 통과를 뜻하지 않는다.
- 현재 Chrome 자동화는 360/390/548px에서 요청 뒤로가기·새로고침, 직거래 검색 결과 선택·상세 위치 저장·편집 취소·복원, 여행 도시/섬/방문지 초안, 달력 확인 버튼, 홈·지도·MY·모드·거래 화면의 넘침과 런타임 오류를 검사한다. 외부 검색은 명시적 테스트 결과, 지도 스크립트는 실패 응답으로 대체해 화면 복구를 확인하며 실제 검색/지도 품질 통과를 주장하지 않는다.
- 브라우저 회귀 검사는 `scripts/browser-audit.py`에 보존했다. Python 3의 Playwright·requests와 Chrome이 설치된 환경에서 `npm run test:browser`로 빌드와 검사를 실행한다. 별도 임시 API·정적 서버와 새 브라우저 세션을 사용해 사용자 데이터와 열린 앱을 변경하지 않는다. 캡처는 실행 결과에 출력되는 임시 `moa-layout-results-*` 폴더에 남는다. 일반 `npm test` 실행에 이 Python 환경은 필요하지 않다.
- ESLint 설정과 `npm run lint`를 추가했다. 타입 검사나 `git diff --check`와 별도로 실행한다. 네이티브 iOS/Android 기기·키보드·스크린리더 동작은 별도 실기기 검증이 필요하다.

## 남은 사항과 다음 우선순위

1. **실계정 운영·여행 인증과 결제**: 카카오·Google·네이버 OAuth 코드 흐름은 구현됐지만 실제 키 검증, 계정 연결 해제·탈퇴 정책이 남아 있다. 본인확인/항공사 증빙 공급자, 심사·이의제기, 실제 PG/webhook/대사·환불 정책도 연결해야 하며 운영 모드 시작은 차단된다.
2. **실제 장소·동선·재고 데이터**: 카카오 검색 키, 해외 장소 검색, 경로 공급자, 판매처별 재고 갱신을 연결한다. 근처 여행자·방문자 통계·추가 이동 시간은 예시이며 실제 GPS 기반 사람 목록/최적 경로로 오인하면 안 된다. AI 인식/한국어 번역은 키와 외부 품질 검증이 필요하고 전용 모델 학습을 수행한 상태는 아니다.
3. **운영/모바일 품질**: 작은 iPhone·Android 실기기 접근성/키보드, 네이티브 보안 초안 저장, CI, 페이지네이션·이미지 저장소, 데이터 50건 이상·오프라인·장시간 네트워크 장애 테스트를 강화한다. 여행 등록 초안의 웹 탭 새로고침 복원은 구현·테스트했고 네이티브 프로세스 재시작 저장은 남아 있다.

추가 출시 점검: 외부 URL 수집의 DNS rebinding/네트워크 egress 방어, 이미지 악성 파일 검사, 민감정보 보관·삭제 정책, 실제 위치 공유 동의, 푸시 알림, 재고 부족/가격 변경 승인, 분쟁 운영 화면. 데모 데이터의 실인증 전환이나 예시 수치를 실제 측정값으로 바꾸는 임의 처리는 하지 않았다.
