# 모아 · 디자인 시스템

## 성격

밝은 화이트 기반에 도시·장소 사진으로 여행의 기대감을 주고, 금액·인증·진행 상태는 짧고 명확하게 보여준다. 한 화면의 주요 행동은 하나로 정하고 파랑은 선택·진행·주 행동에 제한해서 사용한다. 큰 설명 카드와 중첩 카드 대신 여백·행·구분선으로 정보를 묶는다.

| 토큰      | 값      | 용도                       |
| --------- | ------- | -------------------------- |
| canvas    | #F7F8FA | 밝은 앱 배경               |
| paper     | #FFFFFF | 폼·정보 영역               |
| ink       | #191F28 | 기본 텍스트                |
| secondary | #4E5968 | 보조 텍스트                |
| muted     | #8B95A1 | 부가 정보                  |
| green     | #3182F6 | 주 행동·활성 탐색의 블루    |
| darkGreen | #1B64DA | 블루 텍스트 강조           |
| lime/blue | #E8F3FF | 옅은 블루 배경             |
| mint      | #EDF6FF | 선택 상태·인증             |
| lilac     | #F2F4F6 | 비활성·보조 배경           |
| butter    | #FFF6DC | 확인 필요 안내             |
| border    | #E5E8EB | 최소 구분선                |
| danger    | #F04452 | 오류·분쟁                  |

`green`, `darkGreen`은 기존 컴포넌트 호환을 위한 이름이며 실제 색은 블루다. 색상·여백·모서리·문자 크기·모션의 기준은 `apps/mobile/src/theme/tokens.ts`에 둔다.

한국어 기본 글꼴은 웹 Pretendard 및 플랫폼 시스템 sans-serif. 기본 크기는 Hero 28, Page title 23, Section 19, Body 15, Caption 13px이다. 핵심 금액은 24~28px, 보조 문구는 주 정보보다 작고 짧게 둔다. 옅은 파랑 위 흰색 작은 글자를 사용하지 않는다. 터치 영역 최소 44×44. 가격은 KRW 정수 단위로 표시하고 원가·통화·고정 데모 환율을 구분한다.

간격은 4/8/12/16/20/24/32px, 화면 좌우 20px, 카드 radius 18px, 일반 컨트롤 12~16px, 시트 24px를 기준으로 한다. 칩은 선택 기능에만 사용하며 둥근 pill을 기본값으로 남발하지 않는다. 모션은 180/220ms 기준으로 짧게 사용하고 reduced motion 설정을 존중한다.

하단 내비게이션은 홈/둘러보기/+/거래/MY다. 가운데 `+`는 하단 시트로 부탁·여행 시작을 선택한다. 구매자·여행자 모드는 MY·설정에서 변경하고 홈에는 현재 모드만 작게 둔다. 입력·결제 단계는 하단 탭을 숨겨 뒤로가기와 주 행동에 집중한다. 웹에서는 앱 폭을 제한하며 360px 폭에서도 제목·금액·버튼이 겹치지 않도록 `minWidth: 0`, 줄바꿈, 축소 규칙을 적용한다.

프로필·성공률·방문자·거래량 등 예시 수치는 체험 데이터임을 알린다. 샘플 인증을 실제 본인 인증으로 표현하지 않는다. 상품 사진과 여행 사진은 실제 재고·거래 증명이 아니다. 연결되지 않은 결제·정산·본인 인증·푸시 기능은 준비 상태로 설명하고 완료 표시나 가짜 저장을 만들지 않는다.

## 공통 컴포넌트

| 컴포넌트 | 책임 |
| --- | --- |
| `Page`, `Txt`, `Row`, `Stack` | 화면·글자 위계·공통 정렬 |
| `Button`, `IconButton`, `Chip` | 주·보조 행동, 최소 터치 영역, 선택 상태 |
| `Field`, `SearchField` | 입력 레이블, 검색·지우기, 포커스 |
| `Sheet`, `SectionTabs` | 맥락을 유지한 선택, 대화상자 닫기, 탭 전환 |
| `PlaceCard`, `ProductRow`, `Avatar` | 장소·상품·사용자 식별 |
| `MoneyBreakdown`, `StatusTimeline` | 금액 분해와 거래 단계 |
| `RouteMap`, `DestinationPicker`, `TripRoutePicker` | 지도·국가·도시·섬·방문 예정지 선택 |
| `Notice`, `Empty`, `ErrorBoundary` | 오류·빈 상태와 다음 행동 |

MY 메뉴는 `AccountGroup`·`AccountRow`로 그룹 제목과 짧은 행을 사용한다. 인증·결제·직거래 기록·알림 설정은 공통 `Sheet`에 담아 전체 화면 이동을 줄인다. 도움말 질문은 펼쳐서 읽는 구조다.

## 상태 UX

- Loading: 진행 표시, 중복 제출 방지, 기존 입력 유지.
- Empty: '아직 요청이 없어요'와 장소 선택 또는 요청 만들기.
- Error: 사용자가 할 수 있는 재시도·입력 보완을 안내하고 폼 값은 보존. 내부 API 경로·예외 원문은 노출하지 않음.
- Success: 생성한 객체의 상세나 거래로 이동.
- Offline: 연결 오류 화면, 다시 연결; 데이터 저장 성공처럼 표현하지 않음.

키보드·스크린리더를 위해 버튼 역할, 입력 레이블, 선택 상태, 오류 live region을 제공한다. 시트는 Escape/뒤로가기와 닫기 버튼으로 닫을 수 있어야 한다. 권한 거부 시 직접 선택할 수 있는 경로를 제공한다. 위치 미리보기와 예상 추가 이동 시간을 실제 GPS 사람 목록·최적 경로로 표현하지 않는다.

## 벤치마크와 검증

- [토스 UI/UX 가이드](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.html): 정보 우선순위, 쉬운 한국어, 짧은 입력과 피드백.
- [트리플 공식 소개](https://triple.guide/intro): 목적지·일정·장소가 연결되는 탐색 원칙.
- [Grabr 공식 거래 흐름](https://grabr.io/en/how-grabr-works): 사람 간 거래의 확인·대화·수령 후 지급 원칙. 모아의 신규 부탁은 구매자 지정 보상·여행자 수락이며 Grabr의 제안형을 그대로 적용하지 않는다.
- 야놀자·NOL: 사용자 지정 참고 대상으로 목적지·사진·정보의 빠른 탐색만 설계 기준에 반영한다. 현재 실제 앱의 전 화면을 조사·검증했다는 의미는 아니다.

현재 UI 재설계의 자동 테스트·실제 렌더링 검증은 통합 검증 후 [05-validation.md](05-validation.md)에 기록한다. 네이티브 실기기와 5초 이해·30초 등록의 사용자 테스트는 별도 검증 대상이다.
